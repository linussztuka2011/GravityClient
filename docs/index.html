What the application does

GravityClient is a launcher for Minecraft: Java Edition. It manages separate game profiles, installs a curated set of open-source performance and quality-of-life mods into them, and starts the game. It ships with a small companion Fabric mod that renders an optional in-game FPS overlay configured from the launcher.

  • Profiles — each profile is an isolated game directory with its own mods, configuration, worlds and server list.
  • Mod installation — mods are downloaded at runtime from Modrinth using project IDs declared in a manifest, and verified against published SHA-1 hashes.
  • Configuration presets — bundled config overlays (balanced, performance, visual) that tune the installed mods. Existing configuration files are backed up before being replaced.
  • Worlds and servers — the launcher reads and edits the game's own level.dat and servers.dat files so singleplayer worlds and the multiplayer list can be managed outside the game.
  • Game launch — official assets, client JARs and libraries are downloaded from Mojang's own metadata endpoints; Fabric Loader profiles come from Fabric's metadata service.

How Microsoft sign-in is used

Signing in is required for the same reason any launcher requires it: to obtain a Minecraft access token so the player can launch and play the copy of the game they own. Sign-in is optional in the launcher — offline profiles work without an account, but cannot join online servers.

The flow

The application uses the Device Authorization Grant. The launcher never renders a Microsoft login form and never sees the player's credentials — it displays a short code, and the player signs in on Microsoft's own website.

  1. The launcher requests a device code and displays it, along with a link to Microsoft's verification page.
  2. The player opens that page in their own browser and signs in directly with Microsoft, then grants consent.
  3. The launcher polls Microsoft for the resulting OAuth token.
  4. That token is exchanged for an Xbox Live token, then an XSTS token, then a Minecraft access token.
  5. The player's Minecraft profile (username and UUID) is read so the launcher can start the game as that player.

Outside of sign-in, the launcher contacts only launchermeta.mojang.com and textures.minecraft.net (official game metadata and textures), meta.fabricmc.net (Fabric Loader metadata) and api.modrinth.com (mod downloads).

Data handling

  • No passwords are collected, transmitted or stored. Authentication happens entirely on Microsoft's own pages via the device code flow.
  • No servers are operated by this project. There is no backend, no account system and no database. The launcher talks only to Microsoft, Mojang, Fabric and Modrinth.
  • No telemetry or analytics. No usage data, crash reports or identifiers are collected or transmitted anywhere.
  • Tokens stay on the player's own computer. The Minecraft access token and Microsoft refresh token are written to the launcher's local data directory and used only to launch the game and to perform actions the player explicitly requests.
  • Nothing is shared with third parties. No data of any kind leaves the player's machine except the direct API calls listed above.

Planned improvement. Session tokens are currently stored in the launcher's local configuration file. Moving them into the operating system credential store (Windows Credential Manager, macOS Keychain, Linux Secret Service) is a tracked item on the project roadmap.

Compliance

  • No game files are redistributed. The repository contains no Minecraft binaries, assets or decompiled code. All game files are downloaded by the player's own installation from Mojang's official endpoints at runtime.
  • No modification of Mojang binaries. Modding is performed exclusively through the standard, publicly documented Fabric Loader at runtime.
  • No mod JARs are bundled. Third-party mods are referenced by Modrinth project ID and downloaded at runtime. Every mod in the manifest carries its licence name, licence URL and author attribution, which the launcher displays.
  • Ownership is not bypassed. The launcher cannot start an online session without a valid Microsoft account that owns the game; the standard authentication chain is used unmodified.
  • Free of charge. The project is not monetised in any form.
  • Branding. The application does not use Mojang or Microsoft trademarks in its name or logo and states clearly that it is unofficial.

Source code and builds

The full source is public at github.com/linussztuka2011/GravityClient, including the launcher, the companion Fabric mod, the mod manifest and the authentication implementation described above. The relevant file is launcher/src/main/services/microsoftAuthService.ts.

The application can be built and run from source with:

git clone https://github.com/linussztuka2011/GravityClient.git
cd GravityClient/launcher && npm install && npm run build
